# AI 新闻自动采集方案可行性分析

> 目标：不再手动配置 RSS/API 新闻来源，让系统自动从微博、央视、知乎等渠道获取热点新闻，并交给 DeepSeek 生成原创文章。
> 状态：可行性分析（v1.0）

---

## 1. 核心结论

**可行，但必须纠正一个前提：DeepSeek（语言模型）无法自己“上网”抓取新闻。**

- DeepSeek 根据训练数据生成文字，**不具备实时联网能力**；
- 它的 API 默认**不提供网页搜索 / 爬虫**功能；
- 因此“只调用 DeepSeek 就自动获取微博/央视/知乎新闻”在技术上不成立。

正确做法是：**「采集/搜索工具负责拿新闻」+「DeepSeek 负责写文章」**。下面给出三个可行方案。

---

## 2. 方案对比

### 方案 A：RSSHub 聚合采集 + DeepSeek 生成（⭐ 推荐）

RSSHub 是开源 RSS 生成器，一条命令部署，提供微博、知乎、央视等 500+ 渠道的 RSS 路由：

| 渠道 | RSSHub 路由示例 |
| --- | --- |
| 微博热搜 | `https://rsshub.app/weibo/search/hot` |
| 知乎热榜 | `https://rsshub.app/zhihu/hotlist` |
| 央视新闻 | `https://rsshub.app/cctv/news` |
| 微博博主 | `https://rsshub.app/weibo/user/{uid}` |

- 现有采集模块**完全兼容**（仍是 RSS，改一下来源 URL 即可）
- DeepSeek 只负责把新闻改写成原创文章
- 免费、稳定、可扩展、代码改动小

**缺点**：需要自建 RSSHub（Docker 一行启动）；个别路由偶尔失效需维护。

### 方案 B：搜索 API + DeepSeek（Function Calling）

DeepSeek API 支持 **Function Calling**。可以定义一个 `search_news(keyword)` 工具：

1. DeepSeek 分析出想搜的关键词
2. 调用搜索/新闻 API（博查、Bing、百度智能云、NewsAPI 等）拿真实新闻
3. DeepSeek 基于返回结果生成文章

- 更“智能”，可以按热点意图搜索
- 无需维护渠道路由

**缺点**：搜索 API 有费用/配额；国内可用的搜索 API 选择少；需要额外开发工具调用层。

### 方案 C：平台官方 API / 直接抓取（不推荐）

| 渠道 | 公开 API |
| --- | --- |
| 微博 | 开放平台需企业资质，无免费新闻接口 |
| 知乎 | 无公开新闻 API |
| 央视 | 对外 RSS 极少 |

直接爬网页有**反爬、封 IP、法律合规**风险，不推荐作为主要方案。

---

## 3. 方案对比表

| 维度 | A：RSSHub 聚合 | B：搜索 API + Function Calling | C：官方 API / 抓取 |
| --- | --- | --- | --- |
| 实时性 | 高（定时拉取） | 高（按需搜索） | 中 |
| 成本 | 免费（自部署） | 按量付费 | 低/免费 |
| 维护难度 | 低 | 中 | 高 |
| 合规风险 | 低 | 中 | 高 |
| 对现有代码改动 | 小 | 中 | 大 |
| 推荐度 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ | ⭐ |

---

## 4. 推荐实施路径

### 第一阶段：方案 A（快速落地）
1. 服务器 Docker 部署 RSSHub（`docker run -p 1200:1200 diygod/rsshub`）
2. 在现有「新闻来源」里一键添加热门渠道模板：
   - 微博热搜 / 知乎热榜 / 央视新闻
3. 保留现有「按类型筛选 → AI 生成 → 审核发布」流程
4. 每天 8 点定时任务自动采集 + 生成

### 第二阶段：按需增强为 A + B
1. 新增 `src/lib/news/search.ts`：调用搜索 API
2. 用 DeepSeek Function Calling 决定「搜什么」
3. 用于补充 RSSHub 覆盖不到的事件性热点

---

## 5. 对现有代码的改动点（方案 A）

| 文件 | 改动 |
| --- | --- |
| `src/lib/news/sources.ts` | 新增「一键添加热门渠道模板」（微博热搜/知乎热榜/央视） |
| `src/lib/news/rss.ts` | 无需大改（兼容 RSSHub 输出） |
| `scripts/ai-daily.ts` | 定时任务自动采集 + 生成（已实现） |
| `src/lib/ai/prompts.ts` | 提示词改为「基于多条检索新闻综合创作，注明来源」 |
| 前端 `SourceManager.tsx` | 增加「添加热门渠道」按钮 |

---

## 6. 风险与合规

| 风险 | 说明 | 对策 |
| --- | --- | --- |
| 版权 | 直接复制原文有版权风险 | AI 必须原创改写 + 保留原文链接 |
| 平台条款 | 抓取微博/知乎需遵守其条款 | 优先 RSSHub，自用合规风险低 |
| 内容真实性 | LLM 可能「幻觉」编造事实 | 保留原文链接 + 强制人工审核后发布 |
| 成本 | DeepSeek 便宜但搜索 API 按量计费 | 第一阶段纯 RSSHub 免费 |

---

## 7. 最终结论

- ✅ 需求**可行**，但必须采用「**采集工具 + DeepSeek 生成**」的组合；
- ✅ 推荐 **方案 A（RSSHub）**：改动小、免费、稳定，可直接在现有模块上落地；
- ⏳ 方案 B（搜索 API + Function Calling）作为二期增强；
- ❌ 不建议方案 C（直接抓取）。

**建议**：先按方案 A 落地，跑通「自动采集微博/知乎/央视 → DeepSeek 生成 → 审核发布」全流程，再决定是否接入搜索。
